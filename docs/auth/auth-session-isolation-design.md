# 认证、会话与资源隔离重构设计

日期：2026-09-21

分支：`refactor/auth-permissions`
状态：阶段 0 与 A–D 已完成本地实现；实际验证范围与未覆盖项见 [验收记录](./auth-refactor-verification.md)。真实数据库迁移仍需单独授权，真实 OAuth/SMTP/生产尚未验收。

## 1. 已确认边界

- 多个账号、同一种普通用户身份；每个用户独立使用自己的资源。
- 不建立管理员、角色分级、组织、租户或权限配置后台，不引入 RBAC 框架。
- 保留邮箱注册/登录、验证、密码重置、GitHub/Google OAuth、账号注销。
- 保留服务端资源归属校验、会议主持人与参与者规则、API Key/MCP 限制。
- 保留已有公开发布、签名分享入口；“资源隔离”不意味着删除用户主动分享的能力。
- 保留现有品牌和登录卡片，只修正状态反馈及路由过渡，不重新设计视觉体系。
- 在当前本地分支实施；不自动提交、推送、修改线上配置或数据库。

## 2. 方案选择与依据

选择：保留 Better Auth 作为认证提供方。根据用户追加意见，先独立评估升级最新稳定版并完成兼容性验证，再重构应用侧协调层，随后逐模块统一资源隔离。升级按 [阶段 0 实施计划](./better-auth-upgrade-plan.md) 执行；真实数据库迁移尚未执行。

仅修 JWT 回调无法解决多份用户状态、路由竞争和旧请求覆盖；立即更换认证库则同时引入账号、密码、OAuth、Session、API Key 迁移风险。把提供方升级与应用状态重构拆为两个可验证阶段，避免围绕旧版本写入不再需要的兼容逻辑，也便于定位回归。

本次诊断基线：

- 已安装 Better Auth 1.2.12；隔离验证确认全局 `fetchOptions.onSuccess` 被内部请求回调覆盖，JWT 接收没有按预期执行。
- `getSession()` 返回数据不等于更新 `useSession()` 共享状态；当前恢复路径把两者混用。
- 登录返回用户只写入某个 `useAuth()` 实例；路由守卫在有 token、用户仍恢复时可能提前重定向。
- 日志出现一次成功登录约 1.35 秒、随后约 15 秒内 13 次会话查询（各约 1.16 秒）。这些是服务端观测，不是单个页面的完整关键路径测量，也不能直接相加。
- 数据库 5 次只读 ping 为 260–305 毫秒；认证集合当时仅有 `_id` 索引。网络往返和缺索引是独立优化项，尚不能量化各自对登录耗时的占比。

旧 `login-flow-bugs.md` 是历史记录，不作为当前缺陷是否仍存在的证明。

实施补充：1.7.5 无网络隔离诊断确认全局和单请求 `onSuccess` 均执行，新版已修复 1.2.12 的回调覆盖行为；但直接 `getSession` 返回用户后共享 session atom 仍未同步。后续阶段不再围绕旧回调覆盖写兼容补丁，仍需处理唯一会话快照、去重及旧响应隔离。

### 2.1 最新稳定版升级评估（2026-09-21）

阶段 0 已落地：客户端、服务端及官方 API Key 包精确锁定 1.7.5，根锁文件已同步；升级前前端 `~1.2.5` 与服务端 `^1.2.5` 的不同范围不再保留。以下表格记录评估时识别的兼容点；本地隔离验收已通过，但不代表真实 OAuth/SMTP、现有数据库迁移或生产部署已验收。

| 兼容点 | 已核实变化与项目动作 |

API Key 数据迁移必须单独设计并经授权执行：先备份与 dry-run，按已确认的用户类型映射旧 `userId` 到 `referenceId`，补配置标识并检查冲突。保留 Key 哈希、scope、metadata、过期与限流语义，不能要求用户重新生成全部 Key 作为默认迁移方案。先保留旧字段，避免不可逆删除。

回退不只是降版本：新版新建 Key 可能只有新字段。切换前必须验证旧版本能否读取切换后的新增记录；若不能，采用经过审查的双向兼容方案或短暂冻结 Key 创建/修改窗口。备份、恢复步骤和写入窗口明确后，才能在真实环境执行迁移。MongoDB 不直接执行官方文档中的 SQL 示例。

只在隔离、可恢复的验证环境运行新版服务；不能让新依赖经本地自动重启未经确认地连接共享远程库。升级验收覆盖旧密码登录、既有 Session、Google/GitHub 关联、旧通用/MCP Key、创建/撤销/注销清理。全部通过后再开始阶段 A；若存在阻塞，报告具体问题并重新决定顺序，不默默回退旧版。

## 4. 客户端会话契约

### 4.1 唯一快照

UI 只订阅一份用户/会话快照；Better Auth 的内部状态不再与组件本地用户副本竞争。适配器负责把提供方响应转换成快照，凭证仅保存在内存及提供方原有 Cookie 中，不持久化到 LocalStorage。

会话状态与操作状态分开，避免后台刷新导致整个页面回到登录态：

| 会话状态 | 语义 | 受保护页面行为 |
| --- | --- | --- |
| `checking` | 首次恢复或身份变更后的重新确认 | 轻量身份确认提示，不挂载业务请求 |
| `anonymous` | 已明确确认没有有效会话 | 转登录页并保留安全的站内返回地址 |
| `authenticated` | 用户和可用会话凭证已一致确认 | 进入页面，业务数据独立加载 |
| `unavailable` | 无法确认身份：网络、超时或服务异常 | 保留返回目标，提供重试，不伪装成登出 |

操作状态包括空闲、邮箱登录、OAuth 跳转、刷新、退出；表单错误与已有身份分开保存。已登录且凭证仍有效时，暂时刷新失败不清空身份；凭证失效且恢复不可用时暂停受保护操作，不用旧凭证继续发送。

### 4.2 登录与路由

1. 同步获得登录操作锁，立即显示真实等待反馈，防止同一事件循环重复提交。
2. 邮箱登录成功后，以同一代次原子发布用户和 Session 凭证；响应缺字段时只走一次受控恢复，不能凭局部字段宣布成功。
3. UI 只在共享状态确认后导航；移除与守卫竞争的重复跳转，`returnTo` 仍需站内地址校验，拒绝认证页自循环及跨站地址。
4. OAuth 发起不等于已登录；回调后经过同一恢复入口。失败与超时用单次浮动提示（toast）说明，用户取消授权静默返回（只返回 `OAUTH_CANCELLED`，不弹提示、不改登录状态）。
5. 注册、邮箱验证后的自动登录如仍有现有入口，也必须通过同一会话提交路径。
6. 首页请求独立显示加载/错误，不阻塞认证成功；身份确认前不显示假首页。

登录卡片复用现有暖中性 Token、固定 Logo、圆角及基础组件。“正在登录”和“正在进入”分别对应真实阶段；错误可聚焦、可重试，不增加假进度条。Desktop/Mobile 各自维持既有交互模型。

### 4.3 去重、JWT 与请求重试

- 初始化、JWT 刷新、401 恢复均由一个协调器管理；同一会话代次共享在途恢复 Promise。
- 不同时开启提供方自动恢复和自定义恢复两条竞争路径；由适配层明确选择唯一入口。
- JWT 通过已验证可执行的响应回调接收，并与请求对应的会话代次关联；不允许无条件全局回调绕过旧结果过滤。
- JWT 新鲜时不触发 `get-session`；到期前预留刷新窗口，先沿用现有两分钟口径。
- 保留现有 Session/JWT 接口协议；Session 是身份生命周期依据，JWT 只是业务请求凭证，不是第二份登录状态。
- 认证读请求初始超时预算为 10 秒，超时后提供重试；不无限轮询，不把该超时套到大文件上传或长连接。
- 每个业务请求捕获用户 ID 与会话代次；只允许在原账号、原代次下恢复和重试一次。切换到另一账号后绝不自动重放原请求。
- 只有鉴权在业务执行前明确拒绝、且请求体可重放时才能重试。写请求网络超时不自动重试，避免重复创建/删除等副作用。
- 并发旧 401 到达时先比较请求使用的凭证版本，避免已经刷新成功又重复刷新；最终失效只触发一次会话转换。
- 403/404/409/429 和网络/5xx 分别处理，不统一当成 401，也不自动触发退出。

### 4.4 退出、切换账号与跨标签页

- 每次身份变更提升会话代次；失效旧恢复任务，取消可取消请求，晚到结果不能写回用户、JWT 或业务缓存。
- 退出开始即清空本地身份、发布 `anonymous` 并回到登录页，同时清理当前账号缓存、上传显示和 Socket/媒体连接，再完成远端会话撤销。
- 远端退出失败时发布 `signOutFailed` 而不是恢复旧身份：登录页保留持久通知与“重试退出”，退出意图存入当前标签页的 sessionStorage，刷新后继续退出；远端确认前禁止新的登录，也不能伪装成退出成功。服务端变更请求超时不等于已回滚。
- 登录/退出类 Cookie 变更串行协调；取消请求或忽略 JS 响应不能撤销服务器已执行的操作或浏览器已接收的 Set-Cookie。结果不确定时先重新确认，再允许下一次身份变更。
- 跨标签页只广播身份变更通知，不广播 token 或业务数据。接收方失效旧代次、暂停旧账号操作并重新确认 Cookie 会话。
- TanStack Query、Jotai、编辑器与上传等缓存都纳入账号清理清单；用户相关查询使用账号作用域，不能只依赖路由卸载。

### 4.5 上传恢复

新上传元数据绑定当前用户，登录确认前不恢复。遗留无 owner 元数据不能直接归属当前账号：仅在已认证后向服务端校验任务归属，成功才迁移并展示；不存在/无权限不触发全局登出，不展示其文件名。未确认的遗留记录不直接删除，也不自动清理服务端任务。

## 5. 服务端身份与资源边界

认证输出保留 `session / jwt / apiKey` 的区别和 API Key scope。无管理员并不意味着所有凭证等价。

| 入口/资源 | 必须保留的安全规则 |
| --- | --- |
| 私有笔记、标签、摘要、图片 | 以认证用户作为归属来源；列表、搜索、计数、详情和写入均检查归属；不能只在 UI 过滤 |
| 文件、文件夹、上传任务 | 查询及更新同时携带 owner 条件；父目录、移动目标和任务关联文件再次校验；秒传仍限本人 |
| 批量/树操作 | 每个目标及子树均受归属约束；保留现有部分成功或整批拒绝规则、锁和并发版本检查 |
| 会议 | 无游客入会；保留会议/用户绑定的入会凭证、房间成员约束、主持人专属管理操作；主持人不是系统管理员 |
| 通用 API Key | 验证所有者仍存在；历史无 scope 的通用 Key 只具备其所有者的既有业务能力，不获得跨账号访问 |
| MCP Key | 只经 `/mcp-api` 访问本人笔记；写入限 Agent 来源；禁止发布/永久删除/文件/会议；保留子树与字段约束 |
| API Key 管理、注销等敏感操作 | 保留真实 Session/JWT、Origin、防伪造 userId 及验证码等现有要求 |
| 博客、签名预览和分享 | 使用独立公开/签名策略，限制状态、字段、用途和有效期，不复用“已登录即可读取任意 ID”逻辑 |

在各领域统一 actor 传递和归属校验，避免建立一个接收任意集合名称的万能权限函数。查不到/越权的私有资源对外不泄露其存在；迁移时逐入口记录现有响应契约，避免改变公开入口。

HTTP 与 Socket 复用凭证解析领域能力，但 Socket 仍需入会校验和账号注销保护。JWT 校验显式绑定发行者、受众、允许算法及密钥；未知 key ID 最多触发一次协调刷新。缓存公钥不能跳过账号已删除检查，不能混淆 API Key、会议凭证和登录凭证。

保留账号注销 tombstone、在途写锁、主动断开 Socket 和清理顺序；保留密码重置撤销 Session 的行为。既有短期 JWT 最长继续有效 15 分钟的契约本轮不暗中改变，也不得宣称实现了即时撤销全部 JWT。

## 6. 迁移与回退

| 阶段 | 范围 | 退出条件 |
| --- | --- | --- |
| 0：提供方升级 | 以 1.7.5 为候选，独立验证版本、插件、数据兼容与部署运行时 | 旧账号/Key 可用、迁移与回退经过验证；真实数据库执行另获授权 |
| A：基础契约 | 认证适配器、状态协调、JWT 接收、错误分类 | 隔离验证覆盖成功、失败、并发、旧结果；尚不改变业务资源规则 |
| B：客户端接入 | useAuth、路由、认证页面、请求层、缓存/上传/Socket 生命周期 | 邮箱和 OAuth 回调路径一致；旧组件恢复副本无调用方 |
| C：服务端边界 | 凭证解析抽离，逐个核查 Note/File/Meeting/MCP/公开入口 | 资源隔离矩阵完成；现有锁、分享和 Token 限制不回退 |
| D：性能与清理 | 认证索引候选、耗时统计、旧导出清理、文档校正 | 对照基线记录请求数和耗时；确认无旧调用方后删除 |

每阶段形成可独立 review 的 patch；用户要求时才提交。保留现有路由和响应协议，先用适配入口迁移调用方，不一次删除旧模块。提供方升级单独形成 patch 与迁移方案，不和业务资源授权变更混在一起；最新稳定版候选与约束见 2.1。

索引先按实际查询和提供方 Schema 形成清单，检查重复数据和执行计划后提供显式执行方案，不在启动时自动给远程库加索引，不自动删除数据或迁移凭证。数据库距离、索引、签名密钥读取成本分别测量，不承诺前端改动消除所有网络延迟。

公开页面、分享链接、会议发现/详情接口需逐项记录可见字段和现有产品用途；发现与“私人资源隔离”冲突时先提出具体调整，不因本轮重构自行关闭既有协作入口或扩大可见性。

## 7. 验收与证据

按项目约束，不创建、恢复或修改自动化测试文件。执行静态 review、类型检查、lint/build、无落盘的隔离诊断及浏览器/HTTP 实际检查；检查脚本不记录凭证或正文。真实 OAuth 及双账号验证需要可用配置和指定测试账号，无条件时明确列为未验收，不使用真实用户数据做破坏性验证。

必须覆盖：

1. 未登录直接打开首页/登录页、已登录刷新、深链接与非法 returnTo。
2. 邮箱成功/错误/未验证、注册和验证码衔接、OAuth 成功/取消/回调错误。
3. 慢网络、断网、5xx、恢复超时、并发请求与多个 useAuth 消费者。
4. 登录后退出、退出失败、退出后重登、A 切 B、多标签页身份变化；旧 A 请求不能带 B 凭证重发或写入 B 缓存。
5. JWT 新鲜/到期、并发 401、最终失效，以及 403/404/429 不退出。
6. 双账号对列表、搜索、计数、详情、修改、批量、上传、分享和 Socket 的隔离；现有会议参与功能不被误禁。
7. 通用 Key 与 MCP Key 的既有限制、撤销及所属账号注销；MCP 不能通过旧 Note 接口绕过策略。
8. Desktop 与窄屏的等待/错误/重试状态、键盘焦点、触控目标、文本溢出和减少动画偏好。

量化目标：点击后在下一次可渲染帧进入等待状态；一次登录动作仅一次登录提交；同一会话代次同一时刻最多一个恢复请求；有效 JWT 下普通业务请求额外会话查询为零。记录服务端耗时与浏览器导航时序，不把多个请求耗时简单相加，不设置未经测量的“必定秒开”承诺。

构建命令使用仓库现有脚本：客户端 lint、`tsc -b --pretty false`、Vite build；服务端 typecheck；修改 MCP 时补其构建。构建成功不是视觉或安全验收通过。

- 已明确多用户单角色，不沿用“私人单账号”误解。
