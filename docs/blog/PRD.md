## 数据流与公开边界

流程图：[`integration.excalidraw`](./integration.excalidraw)。

`Nubbi Client → 已有 /note/publish → Note → /blog/* → Nubbi Blog Server Components → 读者`

- 现有 Dawn 的 `/post/findWithPage`、`/post/getPost` 已不在当前主服务中注册。
- 新增 `/blog` 只读接口，复用 Note 模型及公开 JSON 路由注册器。
- 仅返回 `published: true`、`deletedAt: null`、密码为空或未设置的文章。
- 列表、搜索、标签、详情共用上述条件；内部状态 `status` 不决定公开性。
- `BLOG_AUTHOR_ID` 可在后端限定一个作者；不设置时展示所有主动发布的无密码文章。
- 白名单响应不返回 userId、password、内部状态、层级、任意 meta 或内容修订号。
- `meta` 是 key/value 数组；只读取 `excerpt`，无摘要时从 Markdown 生成纯文本摘要。
- 文章地址使用稳定 ObjectId；暂不启用无唯一性约束的 meta.slug。
- 正文是 Markdown。默认不解析原始 HTML，禁止嵌入 iframe、视频和脚本。
- 请求与页面使用 no-store，撤回发布后新请求不可继续读取旧正文。

## API

统一响应：`{ code: 1, data, message }`，失败使用 `{ code: 0, message }`。

| 方法与路径 | 参数 | 返回 |
| --- | --- | --- |
| GET `/blog/posts` | offset ≥ 0，limit 1–50（默认 12），q ≤ 100 字，tag ≤ 50 字，order 为 newest / oldest / updated | 标准分页结果 items/total/count/limit/offset/hasMore/nextOffset |
| GET `/blog/tags` | 无 | 最多 100 个公开标签及文章计数 |
| GET `/blog/posts/:id` | 24 位十六进制 ObjectId | 公开文章与 Markdown 正文，不存在或不可公开时 404 |

列表字段：id、title、excerpt、tags、cover、author、date、updatedAt。
详情增加 content；日期采用 date、createdAt 顺序回退。
搜索按标题和标签进行字面匹配，正则元字符转义，查询限制执行时间。
默认使用 createdAt / _id 倒序；最早顺序改为升序，最近更新使用 updatedAt / _id 倒序，均保留稳定分页。

### 接口对接与运行（2026-09-22 实测）

- `NUBBI_API_URL` 是主服务 **API 基地址**，代码自行追加 `/blog/posts`、`/blog/tags`、`/blog/posts/:id`；不要写成以 `/blog` 结尾的地址。参数由 `URLSearchParams` 百分号编码，中文 `q` / `tag` 必须编码后发送。
- 本地开发：`pnpm dev:server` 后使用默认值 `http://localhost:4000`；线上：指向可公开访问的 API 地址（当前为 `http://dawnpoi.site:4000`，需保证该端口可达）。
- **部署前提**：主服务必须是包含 `/blog` 只读路由的版本。线上 `dawnpoi.site:4000` 当前仍是旧构建（`/blog/*` 返回 404、`/tag/list` 返回 401），需要先部署包含本模块的主服务；站点根域由 nginx 做 SPA 回退，不能当作 API 地址。
- 错误映射：列表/标签上游非 2xx 抛 `BlogApiError(status)`；响应不符合 `{code:1,data}` 契约视为 502；连接失败或 8 秒超时视为 503；详情 404 转为 Next 的 notFound，不渲染错误页。
- 实测（2026-09-22，主服务连测试库 `Nubbi`）：分页字段、`order` 校验（非法值 400）、`limit > 50` 拒绝、`/blog/tags` 结构、详情 404 行为均与上述契约一致；`published: true` 为零时列表返回空结果而非错误，空态由前端渲染。
- 前端渲染链路已用同契约真实响应验证：列表（标题/摘要/标签/日期/总数）、标签云与详情页 Markdown（标题、列表、行内代码、代码块）均正确渲染，服务端日志无 `BlogApiError`。

## 阅读流程

- `/` 展示文章流；`/blog` 使用同一列表组件，兼容 Dawn 原入口。
- q、tag、page 存于 URL，支持刷新、分享、浏览器前进和后退；更换筛选重置页码。
- 真正的链接和 GET 表单提供键盘操作与渐进增强，分页替代无限滚动竞态。
- 区分空列表、搜索无结果、接口错误、文章不可用与加载状态。
- 文章提供 GFM、代码高亮、代码复制、阅读时间、标题目录、锚点与返回文章流。
- 响应式布局覆盖手机、平板和桌面，遵循减少动态效果设置与可见焦点规范。
- SEO 使用服务端 title/description/canonical/Open Graph；筛选页不索引。
- 不增加虚假的阅读量、点赞、评论或任何示例生产内容。

## 工程边界

- Next.js App Router 默认使用 Server Components，Promise 形式的 params/searchParams。
- `src/features/blog/api/` 负责运行时契约、请求、适配；组件不直接读 Cookie 或 Storage。
- `src/features/blog/components/` 负责展示；交互逻辑放 hooks；主题样式使用 CSS tokens。
- `src/styles/theme.css` 是唯一颜色来源，集中定义亮色、系统暗色、交互状态和代码高亮颜色。
- 全局样式一次引入主题；组件样式和 Tailwind 只使用背景、文字、边框、强调色等语义变量，不写颜色字面量。
- `NUBBI_API_URL` 为仅服务端的接口地址；`BLOG_SITE_URL` 为 canonical 站点地址。
- 不复制服务端数据库连接或登录密钥到博客，不跨 workspace 引用内部源码。
- 根目录提供 dev:blog、dev:blog:full、dev:all、build:blog、start:blog、lint:blog、typecheck:blog。
- `dev:blog` 仅启动博客，`dev:blog:full` 同时启动主服务与博客；`dev:all` 增加原 Client。
- Nubbi Blog 默认开发／生产端口 3002，避免与其他服务冲突。

## 2026-09-05 阅读与链接预览优化

参考 Shiro 的行内链接、独立链接卡片和按需加载交互，独立实现适合 Nubbi 的阅读增强。
保持低密度阅读界面；正文和标题继续服务端渲染，具体配色遵循后续主题约定。

- 单独成段的 HTTP(S) 链接自动展示卡片，保留作者文字、站点标识与原始目的地址。
- 行内链接提供站点图标、悬停／键盘焦点预览；触屏可用独立预览按钮，原链接仍直接打开。
- 预览展示网页标题、摘要、域名；识别 GitHub 仓库和 npm 包等常见地址，抓取失败保留可用链接。
- 外链信息在卡片进入视口或读者主动预览时加载，不阻塞正文首屏，不嵌入第三方脚本或视频。
- 相同外链请求去重、限并发并短期缓存；站内文章预览每次重新校验发布状态，不缓存正文。
- 新增 Next.js `GET /api/link-preview?url=...`：仅接受 HTTP(S)，白名单输出纯文本元数据。
- 外站抓取限制端口、DNS 公网地址、重定向次数、超时和响应大小；连接固定至已校验 IP，禁止访问内网。
- 元数据抓取与解析放在 `src/features/blog/links/server/`，浏览器请求与交互 hooks 与其隔离。
- 正文图片支持原生对话框放大、关闭和焦点恢复；代码工具栏显示语言，保留复制反馈。
- 支持 GitHub 风格提示块，目录跟随阅读位置；长文章滚动更新经动画帧合并，避免整篇正文重复渲染。
- 列表文章链接在悬停或聚焦后按需预取，点击后提供明确的导航等待反馈。
- 颜色、阴影和提示块状态色全部扩展统一主题；新交互尊重减少动态效果偏好。
- 系统 DNS 为代理合成的 198.18.0.0/15 时，可通过固定 Cloudflare DNS 端点重新获取地址，结果仍经过完整公网校验；环境变量可关闭此兼容行为。
- 脚注保留独立 ID 与返回引用，列表筛选通过受约束的 from 参数随文章导航保留。

预览数据流：`Markdown → 链接分类 → 交互／进入视口 → /api/link-preview → 公网元数据或公开 Note → 预览卡片`。
