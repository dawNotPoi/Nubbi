# Website 工程与产品决策

最后更新：2026-07-14

## 项目目标

Website 是从 Nubbi 笔记体系延伸出的公开博客页面：

- 中文名称：拾光笔记
- 英文品牌：Nubbi Notes
- 当前目标：先建立稳定、独立、可运行和可构建的 Website 工程基础
- 当前阶段不承诺完整博客功能，也不与现有 Client 的产品功能绑定

## 已决定

### 2026-07-14：使用标准 Next.js 工程

采用 Next.js 16.2.10、React 19.2.7、TypeScript、App Router 和 Turbopack。

讨论过 Next.js + Vite 的组合方案，但该方案依赖非官方适配和额外维护，容易受 Next.js 内部实现与插件生态变化影响。Website 目前没有必须使用 Vite 的能力缺口，因此选择标准 Next.js 工程，不引入这层复杂度。

### 2026-07-14：样式采用 Tailwind CSS 4

基础样式使用 Tailwind CSS 4.3.2，并保留少量全局 CSS 负责主题变量、字体和页面背景。当前不引入组件库或独立 Design System。

### 2026-07-14：作为独立 workspace 包维护

- 目录：`website/`
- 包名：`nubbi-website`
- 使用仓库根 `pnpm-lock.yaml`
- 不修改根 `package.json` 来增加 Website 脚本
- 从仓库根目录通过 `pnpm --filter nubbi-website <script>` 运行
- 不直接导入 `client/`、`server/` 或 `mcp/` 的内部源码

### 2026-07-14：初始化结构

当前框架已经包含：

- `src/app/` App Router 结构
- 根布局、全局样式与响应式初始化页面
- “拾光笔记 / Nubbi Notes”基础元数据
- 主题色、系统字体和浏览器图标占位
- ESLint、TypeScript 类型检查与生产构建脚本
- `@/*` 路径别名

### 2026-07-14：主页采用双栏手账方向

- 整体使用暖纸张色、墨色文字和低饱和锈红强调色。
- 桌面端左栏固定展示品牌、短简介和页内导航，右栏承载主文与最新文章流。
- 线条用于表达信息层级，不使用卡片墙、大面积阴影或装饰性插画。
- 品牌优先，不在主页突出头像；作者详细信息留给后续“关于”页面讨论。
- 移动端折叠为单栏，左栏转为顶部品牌区。
- 视觉方向先以 `docs/design/homepage.html` 验证，不直接替换 Next.js 页面。
- 文章页使用窄阅读栏与桌面端固定目录，支持标题层级、引用、代码块和上下篇导航；移动端目录转为横向页内导航。
- 精修阶段保持原有结构，统一主页与文章页的颜色、线条和字体尺度，并优先改善中文长文的行宽、行距与移动端密度。

## 暂缓

以下内容不属于框架初始化阶段，形成明确方案前不实现：

- 博客列表、文章详情、标签、归档等业务路由
- Markdown / MDX 解析与内容渲染管线
- Nubbi Server API 客户端与鉴权
- 客户端状态管理
- Website 专用数据模型
- 搜索、评论、订阅或统计能力
- Dockerfile、CI/CD、托管平台和部署配置

## 待讨论

下一阶段建议按以下顺序形成决策：

1. 内容来源：读取 Nubbi Server 中已发布的 Note，还是使用仓库内 Markdown/MDX。
2. 发布模型：公开条件、草稿行为、文章 slug 和内容更新时间语义。
3. 路由信息架构：首页、文章、标签、归档和关于页面的最小集合。
4. 渲染策略：静态生成、ISR、服务端动态渲染及缓存失效方式。
5. 内容安全：Markdown/HTML 清洗、外链、代码高亮和媒体资源规则。
6. 视觉方向：字体、色彩、排版尺度、深色模式以及是否建立组件层。
7. Web 基础能力：SEO、Open Graph、sitemap、RSS 和分析工具。
8. 发布运维：运行环境、环境变量、错误监控和部署流程。

在第 1 项“内容来源”确认前，不建立博客数据访问层；在发布与路由模型确认前，不创建正式业务路由。
