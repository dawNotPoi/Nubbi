# Code Map

把一段代码（目录、包、整个项目）静态分析成「模块 → 文件 → 函数」三级可下钻的交互图，函数层展示调用关系与实参传递（参数数据流动）。

产物是一个自包含 HTML，浏览器打开即可点击下钻，无需联网。

## 使用方式

```bash
node <skill目录>/scripts/generate.mjs <目标目录> [选项]
```

- `<目标目录>`：要分析的目录，可以是子目录（如 `assistant/api`）或整个项目（如 `assistant`）。
- 常用选项：
  - `--out <文件>` 指定输出 HTML 路径（默认 `<目标目录>/.tmp/code-map/index.html`）。
  - `--no-open` 生成后不尝试用浏览器打开。
  - `--limit <n>` 限制单层最多渲染的节点数，避免超大目录卡顿。

示例：

```bash
# 分析 assistant 整个项目（在 skill 目录下执行）
node scripts/generate.mjs ../..

# 只分析 api 的 src
node scripts/generate.mjs ../../api/src --out ../../.tmp/code-map/api-src.html
```

生成后把 HTML 路径交给用户，或（桌面环境）用默认浏览器打开。

## 图的层级

| 层级 | 内容 | 点击 |
| --- | --- | --- |
| 目录层 | 当前目录下的子目录与源码文件，箭头表示文件间 import 依赖（按目录聚合，数字为依赖条数） | 点目录下钻，点文件进入函数层 |
| 文件层 | 文件内的函数 / 类方法 / React 组件，箭头表示函数调用关系；虚线框为跨文件调用的外部函数 | 点函数查看详情 |
| 函数详情 | 签名（参数与返回类型）、组件 props、入向调用（谁调用它 + 实参）、出向调用（它调用了谁 + 实参） | 点函数卡片或从文件层进入 |

左侧树形目录可随时跳转；顶部面包屑可返回上层；搜索框可按文件名或函数名定位。

## 参数数据流动的说明

- 函数层的调用箭头标签展示**调用点实参**（如 `foo(a, b)`），配合函数详情里的**形参名 + 类型**，即可看出「什么数据从哪里流入、流到哪个形参」。
- 组件卡片展示 props 结构与类型，父组件传参 → 子组件消费。
- 跨文件调用会显示为虚线外部节点，点击可跳到被调用函数所在文件。
- 静态分析的边界：动态 import、`eval`、装饰器/依赖注入的运行时装配、React Context/Store 的运行时数据流只能显示声明与类型，无法追踪真实数据移动；这类调用会标记为「外部」。

## 注意事项

- 首次使用需要安装依赖：在 skill 目录执行 `npm install`（只有 `ts-morph` 一个依赖）。
- 分析前会自动跳过 `node_modules`、`dist`、`build` 等目录。
- `@/` 之类的路径别名：优先读取 `<目标目录>/tsconfig.json` 的 `paths`；找不到 tsconfig 时别名可能无法解析，依赖边会缺失但不影响层级浏览。
