# Conversation Summary

仅在用户明确要求总结当前对话或将对话落地为文档时使用。

## 执行流程

1. 判断用户是否已经说明“创建新文档”或“更新已有文档”。如果没有，先询问用户，本轮不要调用写工具。
2. 更新已有文档时，先使用合适的只读工具搜索并读取目标文档，确认目标和当前内容。
3. 根据当前对话生成 Markdown，不补写对话中没有出现的事实。
4. 从当前可用工具中选择描述和 Schema 最适合文档创建或更新的工具，不依赖固定 Server 或工具名称。
5. 等待工具真实返回后再说明是否落地成功，并在回复中给出 Server、工具名和返回的文档标识。

## 文档结构

```markdown
# 对话总结

## 用户目标

## 已确认需求

## 关键决策

## 已完成事项

## 待办事项

## 风险与问题

## 相关结果

## 下一步
```

没有内容的章节写“暂无”，不要删除固定章节。

如果没有可用的文档写入工具，直接在聊天中返回完整 Markdown，并明确说明当前没有合适的 MCP 工具，因此尚未落地。工具调用失败或被拒绝时如实报告，不得声称已经保存。
